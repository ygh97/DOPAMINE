# 엔진 검증

엔진을 고친 뒤 아래 순서로 확인한다. 하나라도 기준을 벗어나면 수치를 다시 조정한다.

## 1. 단위 테스트

```bash
npm test
npx tsc -p packages/engine
```

엔진 23개(시세 엔진 + 호가창 `exchange.test.ts`)가 모두 통과해야 한다: 같은 seed 재현, 시작가·PER 정확, 숨은 상태 비노출, OHLC 일관성, 업종 상관, 폐지·상장·회생·병합·승격, 호가 단위, 호가 교차 없음, 가격·시간 우선, 제곱근 충격, 재고 기울기, 가격이 지나간 지정가 체결.

## 1-1. 봇 시뮬레이션 (호가창·봇·세력까지)

```bash
npm run sim:bots     # 봇 100 + 세력 20 + 고래 10, seed 6개, 약 30초. --opt '{"kappa":0.0004}'로 엔진 수치를 바꿔 볼 수 있다
```

목표: 50배 졸업(2026-10-23 전: 20배) 비율은 사용자와 다시 정함, 100배 전설 2~3%, 주식 중앙값 1.5~3배, tick 최대 100ms 안. seed마다 편차가 커서 seed 12개(`tools/sim-bots.ts 1 2 … 12`)로 확인하면 안정적이다. 결과는 SPEC 5-2장에.

## 2. 1주 시즌 시뮬레이션

```bash
npm run sim          # 1주, seed 3개 병렬, 약 16초
npm run sim:quick    # 1일, 수치를 여러 번 바꿔 볼 때 (약 3초)
```

출력의 기준:

| 항목 | 기준 |
|---|---|
| 대형주 가격 배수 (1시간 간격 최저~최고) | 대부분 0.4~3배 안. 밖으로 자주 나가면 `epsStep`·`epsHalfLife`·`epsBand`를 조정한다 |
| 코인 | 대부분 0.35~3.5배 (EPS가 없어 앵커 회귀만 받는다) |
| 신흥주 개수 | 마지막까지 10개 |
| 승격 | `maxNewGrowth`(5) 이하, 시점이 1주 동안 퍼져 있을 것 (출력의 "승격 시점") |
| 폐지 | 1주 30~45건. 관리종목 대비 해제가 절반 이상 |
| 뉴스 | 1주 약 6만 건 |

참고 기록 (2026-10-21, seed 1·2·3, 승격 2회+간격 도입 후): 승격 5 (15·45·75·105·135시간 무렵), 관리종목 117~153, 해제 80~112, 병합 13~18, 폐지 37~49, 신흥주 10개.

## 3. 숫자를 바꿀 때

- 파라미터는 `packages/engine/src/market.ts`의 `DEFAULT_OPTIONS`와 `KIND`에 있다.
- 바꾼 값과 이유를 `SPEC.md` 5·6장에 반영한다.
- 원인을 모르면 `tools/sim-week.ts`(엔진만)나 `tools/sim-bots.ts`(호가창·봇까지)에 측정을 추가해서 본다.
